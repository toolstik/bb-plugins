# LiteLLM Agents для BB

Плагин добавляет два подключения в стандартный выбор агента BB:

- **LiteLLM / Claude Code** запускает установленный Claude Code через Anthropic Messages API корпоративного шлюза.
- **LiteLLM / Codex** запускает установленный Codex CLI через Responses API корпоративного шлюза.

Личные провайдеры Claude Code и Codex остаются доступны одновременно с корпоративными. Глобальные конфигурации CLI и личные токены плагин не меняет.

## Как пользоваться

1. Создайте чат в BB и выберите `LiteLLM / Claude Code` или `LiteLLM / Codex` в обычном списке агентов.
2. Выберите модель корпоративного шлюза в обычном списке моделей.
3. Отправьте задачу. Действуют выбранные в BB разрешения на инструменты.

Плагин загружает каталог через `GET /v1/models` с правами вашего virtual key. Известные embedding, speech и image модели исключаются. Наличие модели в каталоге не подтверждает совместимость с инструментами конкретного агента.

Для начала используйте Claude Code с моделью Anthropic, Codex с моделью OpenAI. Переключение модели внутри выбранного агента поддерживается. Переход с Claude Code на Codex требует новой сессии или отдельной передачи контекста.

## Установка

Требуются BB 0.49.0 или совместимый, SDK 0.6.132, установленные `claude` и `codex`. Зависимости зафиксированы в package-lock.json.

```sh
npm ci --legacy-peer-deps
npm test
npm run typecheck
bb plugin build .
bb plugin install .
```

Плагин использует установленный CLI, а не bundled Claude CLI из Agent SDK. При нестандартном расположении задайте `claudeExecutable` и `codexExecutable` в настройках плагина. Установщик плагина не устанавливает и не обновляет ваши CLI.

## Ключ

В настройке `keyFile` укажите приватный dotenv-файл на исполняющей машине. Он должен содержать одну переменную `LITELLM_API_KEY` и иметь права `600` на macOS/Linux. Содержимое файла не нужно вставлять в чат или исходники.

Создание файла через защищенную форму BB:

```sh
bb secret request LITELLM_API_KEY \
  --purpose 'Подключение корпоративного LiteLLM' \
  --describe LITELLM_API_KEY 'Персональный virtual key корпоративного LiteLLM' \
  --write-env /absolute/private/path/credentials.env

bb plugin config litellm set keyFile /absolute/private/path/credentials.env
```

Файл должен находиться вне репозитория. Путь поддерживает `~/`. На удаленной машине нужен свой файл по указанному пути: ключ не пересылается с сервера BB на другие host автоматически.

Корпоративный ключ читает только bridge плагина. На loopback-адресе bridge поднимает прокси с временным токеном; корпоративный ключ подставляется при запросе к шлюзу. Ключ не передается в provider options, argv, события окружения BB или дочерние CLI. Удаление файла прекращает доступ; перехода на личную авторизацию нет.

Это не изоляция секрета от произвольного локального кода с правами пользователя. Агенту с полным доступом к файловой системе нельзя предоставлять задачу читать приватный файл.

## Настройки

Откройте настройки установленного плагина **LiteLLM Agents** или используйте `bb plugin config litellm`.

| Настройка | Назначение |
| --- | --- |
| `baseUrl` | Корень LiteLLM, по умолчанию `https://llm.finstar-ai.cc`. Суффикс `/v1` нормализуется автоматически. |
| `keyFile` | Путь к приватному файлу на исполняющей машине. |
| `claudeExecutable`, `codexExecutable` | Необязательные пути к установленным CLI. |
| `claudeDefaultModel`, `codexDefaultModel` | Предпочтительная модель, если она есть в каталоге. Пустое значение выбирает первую доступную. |
| `modelAliases` | JSON-объект: имя из каталога -> канонический id, подтвержденный поддержкой компании. |
| `claudeModels`, `codexModels` | JSON-массив разрешенных моделей для каждого движка; `[]` показывает все чат-модели. |

Имена каталога не зашиты в код. Псевдонимы не выводятся из названий автоматически. Например, сопоставление из корпоративной инструкции:

```json
{
  "01 Top - OpenAI - GPT-6.1 Sol": "gpt-6.1-sol",
  "02 Coding - OpenAI - GPT-5.3-Codex": "gpt-5.3-codex"
}
```

Каталог внутри bridge кешируется на 60 секунд. Смена ключа инвалидирует кеш. Чтобы принудительно обновить подключения после изменения каталога, перезагрузите плагин и откройте выбор модели заново:

```sh
bb plugin reload litellm
bb provider models litellm-codex
bb provider models litellm-claude-code
```

Используется HTTPS с обычной проверкой сертификата. HTTP разрешен только для loopback-тестов. Плагин не отключает TLS для внутреннего шлюза с самоподписанным сертификатом.

## Проверки

`npm test` проверяет каталог, ротацию ключа, приватность файла, прокси, передачу потокового ответа, ошибки и отказ при отсутствии ключа. Две conformance-проверки опубликованного SDK проверяют JSON-RPC, события, запуск, продолжение и fork сессии, остановку и восстановление на scripted/fake исполнителях. Отдельная проверка запрещает приватные SDK-импорты.

Ручная проверка на настоящем шлюзе запускает выбранный установленный CLI, просит записать и прочитать один файл в пустом временном каталоге, затем освобождает сессию. Это платный запрос согласно бюджету корпоративного ключа:

```sh
node scripts/smoke.mjs codex /absolute/private/path/credentials.env gpt-6.1-sol
node scripts/smoke.mjs claude-code /absolute/private/path/credentials.env 'имя модели из каталога'
```

Скрипт также принимает четвертым аргументом base URL и пятым id существующей сессии для проверки продолжения после перезапуска bridge. Он не читает ключ в собственный вывод.

Результаты проверки текущей установки приведены в `VALIDATION.md`.

## Ограничения версии 0.1.0

- Тарифы Fast/Ultrafast и выбор reasoning effort не предлагаются: `/v1/models` не дает подтвержденных возможностей каждой модели. Плагин не отправляет универсальные overrides этих параметров.
- Каталог slash-команд CLI, отдельные карточки Goals и подписочные usage-баннеры не добавлены. Доступны обычные инструменты и разрешения агента, plan, compaction и fork.
- Произвольные модели шлюза могут не поддерживать агентный цикл. Фильтрация известных нечатовых моделей не является полной матрицей совместимости.
- Ошибки upstream передаются как HTTP-статус с безопасным текстом. Для подробной диагностики нужно обращаться к журналам LiteLLM: произвольный ответ ошибки не транслируется в CLI.
- Bridge адаптированы из BB под MIT. Снимок указан в `vendor/UPSTREAM.json`, изменения в `vendor/LITELLM.patch`. Обновления BB и CLI требуют повторной проверки совместимости.

## Сопровождение

При обновлении снимка сохраняйте `vendor/LICENSE.bb`, обновляйте commit в `vendor/UPSTREAM.json`, переносите изменения из `vendor/LITELLM.patch` и запускайте все проверки до установки. Host и server используют публичные экспорты `@get-bb/plugin-sdk`; импорты приватных `@bb/*` пакетов запрещены.
